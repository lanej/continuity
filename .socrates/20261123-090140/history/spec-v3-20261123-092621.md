## Problem Statement

The user suspects Beads' issue-oriented model is a poor foundation for breaking down work and preserving decisions across Studio, Publisher, Producer, and their workflow. Specify a bounded Dolt proof before migration to test a workflow-owned model against those needs. Publisher is Octo Manager; Producer is Worktree Manager. Octo knows publish dependencies and does not own the work graph. One shared authoritative model must own the work's full lifecycle and reasoning across sessions, with generated document views and full history.

### Acceptance scenario

1. Session A creates one body of work with an assumption, a requirement and decision depending on it, an approved specification, and a decomposition containing affected and unrelated tasks. Producer records a controlled allocation receipt; Studio starts a controlled affected attempt.
2. Invalidate the assumption with evidence. Show the transitive affected set, preserved original rationale, hold, and pause request. Withhold acknowledgement once: the attempt remains pause-requested and advancement is blocked. Acknowledge through the controlled adapter: only then is the attempt paused. Unrelated work remains runnable.
3. End the harness process and reopen the same Dolt database from session B. Recover the work and hold. Reject an agent attempt to clear it and an operator attempt using a stale expected revision.
4. The operator records a supported reassessment at the current revision, addressing the invalidated basis through a revised specification/plan or documented replacement basis. Do not silently turn the old assumption valid. Clear only the covered current holds; resume is a distinct command/event. An outstanding later invalidation cannot be cleared by an earlier reassessment.
5. Resume, retain verification bound to the approved execution baseline and fixture source revision, and show that recording the result and publication intent does not make it stale. A relevant baseline or source change must make old verification inapplicable; obtain current verification before proceeding. Record a controlled Publisher request/receipt and confirmed delivery. Exercise an uncertain receipt before confirmation without duplicating the effect on retry. Retain historical evidence rather than rewriting it to match current work.
6. Regenerate document views and retain current-state, semantic-event, and Dolt-history evidence. Report whether the model earned a next integration slice; do not claim live tool acceptance.

Run a small reuse variant of the same scenario: session B discovers and attaches existing canonical requirement, decision, and assumption records to a second work item. Assert equal referenced IDs and unchanged logical record counts; retain distinct work/task/attempt identities. Invalidate the shared assumption and verify that both affected active uses receive holds and confirmed controlled pauses. Preserve pinned historical baseline references, reject dangling/duplicate attachments, and demonstrate that clearance covering only the first work item's holds leaves the second held. This variant proves sharing rather than merely recovering one session's copied content.

### Feedback and failure checks

Implement and run the smallest persistence/history round-trip first. Then run the integrated scenario and small reuse variant with deterministic failure branches. Target failures that distinguish the contract: lost/duplicate command results, stale revisions, transitive invalidation including shared references, dangling/duplicate attachments, unrelated-work isolation, missing pause acknowledgement, unauthorized/stale clearance, stale verification, uncertain publication, and process restart. No production-scale benchmark or broad test suite is required.

Any required case failing makes the proof incomplete or failed. Preserve the failure evidence and revise within scope; do not substitute a weaker test or proceed to migration. Storage semantics that cannot provide consistent current state plus attributable history are a reason to revise/stop the Dolt approach, not hide the gap behind a successful SQL insert.

### Known limits

Controlled adapters cannot establish real worker interruption, actual checkout allocation/removal, GitHub publication, operator authentication, distributed/offline synchronization, multi-host recovery, or production concurrency/scale. The local revision guard demonstrates conflicting commands are rejected; it does not establish a production deployment topology. History survives tested clean process restart; power-loss recovery and remote backup/restore remain unproven. No branch/merge user workflow is required.

## Proposed proof shape

Use explicit records and typed relationships for work, sessions, requirement/assumption/decision revisions, specification baselines, tasks, attempts, verification evidence, effect requests/receipts, holds, and reassessments. Keep containment, task ordering, reasoning reliance, and publish dependencies semantically distinct. Exact table layout is an implementation choice; storing everything as unrelated issue descriptions would not satisfy the relationship and impact criteria.

Requirements, assumptions, and decisions have canonical logical IDs independent of their referring session or work item. Provide lookup and explicit attach/reference commands; ordinary discovery and reuse must not clone content into new authoritative records. Multiple work items may reference one canonical record. Frozen baselines pin `(canonical ID, revision)` for historical reproducibility, while current applicability checks traverse shared references and detect invalidated relied-on revisions. Rendered excerpts are views and do not create authoritative copies. A material revision adds history under the same logical identity; a genuinely distinct scoped record requires explicit creation and provenance to its source when derived. Do not infer semantic equivalence from similar text or automatically merge distinct records. The bounded proof establishes explicit lookup-and-reference reuse, not general natural-language duplicate detection.

Invalidation resolves the full affected reference set within the isolated database and records all affected holds under the command transaction/guard strategy; it must not update only the initiating work item or partially accept stale fan-out. Reassessment identifies the exact holds and affected uses it clears; reassessing one work item cannot silently clear another work item's hold. Historical baseline references remain inspectable even when current use is suspended.

The common command layer validates actor capability, command identity, expected revision, references, and transition preconditions before accepting changes. The operator capability is supplied by the trusted harness entry point, not an agent-controlled actor label. The proof's trust separation is deliberately controlled, not production authentication. Mutations and semantic events must be atomic; test and document how accepted SQL changes acquire attributable Dolt history, including retry/failure behavior at that boundary. No network daemon is needed to prove these semantics.

Use distinct revision concepts. The command concurrency revision advances with every accepted state mutation and guards writes using an expected revision. An immutable approved execution baseline identifies the approved specification/plan revisions and relied-on requirement, decision, and assumption revisions; a source revision identifies the controlled code/input snapshot. Verification binds to the baseline/source pair. Recording evidence, receipts, or lifecycle observations changes the command revision but does not itself change the baseline or source. Replacing the approved specification/plan or its relevant requirements/decisions changes the baseline; changing the source changes the source revision; invalidating a relied-on assumption suspends applicability immediately through the hold. Historical verification remains inspectable and cannot silently become applicable to a new pair.

Invalidation records a durable hold before requesting pause from a controlled worker. An unacknowledged or failed pause remains visible and prevents advancing affected work; never report it as paused. Reassessment cannot undo confirmed external effects. Evidence and prior results remain historical facts, with current applicability separate. This proof may simulate confirmations but cannot use them as live delivery evidence.
